# 복지 공고 검색 → 리포트 → 카카오톡

## 도구 이름 규칙

MCP 도구는 **접두사 없이 접미사로만** 지칭한다. 설치 경로에 따라 접두사가 다르다.

| 설치 경로 | 실제 도구 이름 |
|---|---|
| 이 플러그인의 `.mcp.json` | `mcp__playmcp__bokjini-get_welfare_list` |
| claude.ai 커스텀 커넥터 | `mcp__claude_ai_PlayMCP__bokjini-get_welfare_list` |

사용하는 도구: `bokjini-get_welfare_list`, `bokjini-rank_candidates`, `bokjini-get_welfare_detailed`, `KakaotalkChat-MemoChat`. 세션에 노출된 이름 중 이 접미사를 가진 것을 쓴다.

## 도구가 없을 때 — 실패 신호로 판별한다

PlayMCP 게이트웨이는 **도구함에 담긴 도구만** 노출한다. 설치했어도 OAuth 미인증이거나 도구함에 복지니·나챗방을 담지 않았으면 도구가 없다.

**노출된 도구 목록을 훑어 미리 판정하지 않는다.** 세션에 따라 MCP 도구가 지연 로딩(deferred)이라 이름만 있고 스키마가 없을 수 있다. 목록에 안 보인다고 중단하면 정상 설치된 사용자를 막게 된다. **첫 호출을 프로브로 삼아, 실패 방식으로 원인을 가른다.**

| 신호 | 판정 | 대응 |
|---|---|---|
| 스키마 미로드 | 지연 로딩 | `ToolSearch("select:...")` 로 먼저 불러온다. **정상이다** |
| 지연 목록에도 이름이 없음 | 미설치 | 안내 1번 |
| 인증·OAuth 오류 반환 | 미인증 | 안내 2번 |
| 도구 이름 해석 불가 / tool not found | 도구함 미담김 | 안내 3번 |
| `{"result":[]}` | **정상 응답** | 검색 결과 0건. 중단 금지 — 2단계의 재시도 규칙으로 처리한다 |

마지막 줄이 가장 중요하다. 빈 결과는 흔하다(지자체 검색은 자주 비어 있다). 이걸 도구 없음으로 오판하면 멀쩡한 설치에 재설치를 시킨다.

복지니 호출이 위 표의 **미설치·미인증·미담김** 중 하나로 실패하면 절차를 중단한다. **웹검색이나 기억으로 대체하지 않는다.** 복지 공고를 지어내면 사용자가 관공서에 헛걸음한다. 아래 안내만 출력하고 끝낸다.

```
PlayMCP 복지니 도구에 연결하지 못했습니다. 아래 순서로 확인하세요.

1. 설치    /plugin marketplace add murbachovski/bokji-alert
           /plugin install bokji-alert@bokji-alert
2. 인증    /mcp → playmcp 선택 → 카카오 계정 OAuth
3. 도구함  https://playmcp.kakao.com/toolbox 에서
           "복지니" 와 "카카오톡 나챗방" 을 도구함에 담기
           (게이트웨이는 도구함에 담긴 도구만 노출합니다)
4. 재시작  Claude Code 세션을 새로 시작한 뒤 /bokji 재실행
```

`KakaotalkChat-MemoChat` 의 부재도 **보내 봐야 안다.** 1단계 질문 시점에는 알 수 없으므로 선택지를 미리 빼지 않는다. 6단계 전송이 도구 부재로 실패하면 그때 7단계에서 알린다 — 리포트는 이미 발행돼 있으므로 잃는 것은 없다.

claude.ai 커스텀 커넥터로 붙여 둔 경우(`mcp__claude_ai_PlayMCP__*`)도 충족이다. 접두사가 아니라 **접미사만** 본다.

## 절차

### 1. 프로필 로드

`~/.claude/bokji-profile.json` 을 읽는다. 플러그인 디렉터리가 아닌 `~/.claude/` 에 두는 이유: 플러그인 업데이트 시 캐시가 교체되어도 살아남는다.

#### 파일이 없으면 — 첫 실행

**`/bokji` 인자에 이미 들어 있는 값을 먼저 채운다.** (`/bokji 30세 서울 성북구 주거` → `age`, `province`, `district`, `interest_theme`) 그리고 **비는 항목만** 아래 문구로 **평문 한 번에** 묻는다. `AskUserQuestion` 을 쓰지 않는다 — 나이는 자유 입력이고 시군구는 열거값이 200개 넘어 버튼에 담기지 않는다.

```
첫 실행입니다. 아래를 한 번에 알려주세요. 모르거나 해당 없으면 건너뛰어도 됩니다.

 · 나이       (필수)
 · 사는 곳    시도 + 시군구
 · 가구상황   저소득 / 다자녀 / 장애인 / 한부모·조손 / 다문화·탈북민 / 보훈대상자
 · 관심사     주거 / 일자리 / 보육 / 교육 / 신체건강 / 서민금융 ...
 · 부양가족   나이와 관계 (없으면 "없음")

예) 30살, 서울 성북구, 해당없음, 주거, 3세 자녀 1명
```

답을 파싱해 아래 스키마로 `~/.claude/bokji-profile.json` 에 저장하고, 저장했다는 사실과 경로를 **한 줄** 알린다(다음부터 안 묻는다는 것도 함께).

정규화 규칙:

- `province` · `district` 는 `bokjini-get_welfare_list` 의 **열거값과 정확히 일치**해야 한다. "서울" → `서울특별시`, "성북" → `성북구` 로 맞춘다. 열거값에 없는 지명이면 `district` 를 **생략**한다(넣으면 검색이 통째로 빈다).
- "해당없음" · "없음" · 무응답은 **키를 만들지 않는다.** 빈 문자열이나 `null` 을 넣지 않는다.
- `age` 만 사실상 필수다. 나이를 끝내 안 주면 `age` 없이 진행하되 `life_cycle` 도 추측하지 않는다.

#### 스키마

```json
{
  "age": 30,
  "province": "서울특별시",
  "district": "관악구",
  "household_type": "저소득",
  "interest_theme": "주거",
  "dependents": [
    { "age": 3, "relation": "자녀" }
  ]
}
```

모르는 값은 넣지 않는다. `age` 는 확인된 경우에만 넣는다. `dependents` 는 부양 중인 가족이 있을 때만 넣는다(없으면 키 자체를 생략).

**`dependents` 가 핵심이다.** 복지 제도는 신청자가 아니라 **아이·부모·노인 각각의 나이**에 붙는다. 50대 보호자와 3세 자녀 가구에서 실제로 받을 수 있는 것은 거의 전부 `life_cycle: 영유아` 쪽에 있고, 신청자 본인의 `중장년` 검색에서는 하나도 나오지 않는다. 부양가족을 놓치면 검색 자체가 빗나간다.

#### 파일이 있으면

**다시 묻지 않는다.** 이번 요청에서 다른 조건을 줬으면 그 값이 이번 실행에 한해 프로필을 덮어쓴다.

단, 이번 요청 값이 저장값과 **충돌하면**(나이가 다르다, 사는 곳이 다르다, 신분이 바뀌었다) 검색 후 마무리 단계에서 `AskUserQuestion` 으로 한 번 확인하고 저장한다. 나이는 해마다 달라지므로 이 확인이 없으면 프로필이 조용히 낡는다.

```
저장된 프로필: 20세 · 서울 성북구 · 대학생
이번 요청:     30세 · 결혼 예정

프로필을 이번 값으로 갱신할까요?   [갱신]  [이번만 쓰기]
```

**조용히 덮어쓰지 않는다.** 사용자가 일부러 다른 조건으로 한 번 검색해 보는 경우가 있다.

기존 프로필에 `dependents` 가 없을 수 있다(구버전 스키마). 그때는 이번 요청에 부양가족이 등장하면 그 값을 쓰고, 저장 파일도 갱신한다. 나머지 키는 있는 그대로 읽는다.

#### 전달 방식 — 매번 묻는다

프로필이 이미 있어도 이 질문은 **매 실행마다** 한다. `AskUserQuestion` 한 문항으로 묻는다(선택지가 셋뿐이라 버튼이 맞는다). 첫 실행이라면 위 평문 프로필 질문에 답을 받은 **직후**에 이어서 묻는다.

| 선택지 | 아티팩트(5단계) | 카카오톡(6단계) |
|---|---|---|
| 터미널에만 요약 | X | X |
| 웹사이트만 | O | X |
| 웹사이트 + 카카오톡 | O | O |

**"카카오톡만" 은 선택지에 없다.** 카카오톡은 200자라 공고 상세가 안 들어가고 리포트 링크가 곧 본문이다. PreToolUse 훅이 링크 없는 전송을 차단하므로, 아티팩트 없이 카톡만 보내는 경로는 존재하지 않는다. 이 조합을 사용자에게 제시하지 않는다.

사용자가 이번 요청에서 이미 방식을 지정했으면(예: "카톡으로 보내줘", "웹으로만", "그냥 알려줘") 다시 묻지 않고 그대로 따른다.

세 선택지를 항상 그대로 제시한다. 나챗방 도구의 부재는 전송을 시도해야 드러나므로(위 **도구가 없을 때** 참조) 미리 선택지를 빼지 않는다.

### 2. 검색 — `bokjini-get_welfare_list`

- `search_word` 는 **구체적인 키워드 1개**. 문장을 넣지 않는다. (예: "주거", "취업", "월세")
- 프로필 → 필터 매핑:
  - `age` → `age`
  - `province` / `district` → 그대로 (열거값과 정확히 일치해야 함)
  - 나이·상황 → `life_cycle`: 영유아 / 아동 / 청소년 / 청년 / 중장년 / 노년 / 임신·출산
  - `household_type`: 다문화·탈북민 / 다자녀 / 보훈대상자 / 장애인 / 저소득 / 한부모·조손
  - `interest_theme`: 신체건강 / 정신건강 / 생활지원 / 주거 / 일자리 / 문화·여가 / 안전·위기 / 임신·출산 / 보육 / 교육 / 입양·위탁 / 보호·돌봄 / 서민금융 / 법률 / 관계개선 / 에너지
- **판단할 수 없는 필터는 추측하지 말고 생략한다.**
- 결과가 없으면 필터부터 줄여 재시도. **재시도 최대 2회.** 그래도 없으면 선택한 전달 방식에 따라 5단계 또는 7단계로 가되 "조건에 맞는 공고 없음"으로 처리한다.

**가구 구성원별로 검색한다.** `dependents` 가 있으면 신청자 본인 1회로 끝내지 않는다.

| 구성원 | 검색 축 |
|---|---|
| 신청자 본인 | 본인 `age` → `life_cycle`, `province`/`district` |
| 부양가족 각각 | 그 사람의 나이 → `life_cycle`, 같은 지역 |

지자체(`scope: local`) 와 중앙부처(`scope: national`) 는 겹치지 않는 제도를 담고 있다. 지역 제도는 `district` 를 넣고 `local` 로, 전국 제도는 `national` 로 **따로** 부른다. 호출은 병렬로 보낸다.

### 3. 후보 선별 → `bokjini-rank_candidates`

전체 결과를 그대로 넘기지 않는다. 이 도구는 후보 레코드 전체를 다시 입력으로 받으므로 페이로드가 크다.

- 프로필에 부합하는 **최대 8건**으로 먼저 잘라낸다.
- `user_profile` 은 프로필과 이번 요청을 합친 한두 문장 요약. 부양가족이 있으면 **나이와 인원을 명시한다** (예: "만 3세 자녀 1명, 외동이라 다자녀 아님").

**잘라내기 전에 배제 사유를 확정한다.** 검색어·생애주기가 맞아도 실제로는 못 받는 것이 섞여 들어온다. 아래를 확인해 걸러내고, **걸러낸 항목과 사유를 남긴다**(5·7단계에서 쓴다).

| 배제 축 | 예 |
|---|---|
| 연령 컷오프 | 부모급여는 만 0~23개월 — 3세는 종료 구간 |
| 신청 시기 1회성 | 첫만남이용권·출산장려금 — 출생 직후 신청 건 |
| 가구 요건 | 다자녀 제도 — 자녀 1명은 미달 |
| 소득·자격 요건 | 저소득·장애·한부모 전제 제도 — 프로필에 근거가 없으면 "확인 필요"로 분리 |

요약의 `life_cycle` 이 `영유아` 라고 해서 3세가 다 되는 게 아니다. 애매하면 `bokjini-get_welfare_detailed` 의 `target`·`criteria` 를 보고 판단한다. 배제 사유는 사용자에게 **가장 값나가는 출력**이다 — 헛걸음을 막아준다.

### 4. 상세 조회 — `bokjini-get_welfare_detailed`

랭킹 **상위 3~6건**에 대해 호출한다. 기본은 3건이고, 서로 성격이 다른 제도가 더 있으면(예: 현금 지원 / 돌봄 서비스 / 의료비) 6건까지 늘린다. 7건 이상은 리포트가 산만해지므로 늘리지 않는다. 호출은 한 번에 병렬로 보낸다.

**enum 변환 필수.** 후보의 `provider` 는 `"중앙부처"` / `"지자체"` 이고, 상세 도구는 `"national"` / `"local"` 을 요구한다.

| 후보 `provider` | 상세 도구 `provider` |
|---|---|
| 중앙부처 | `national` |
| 지자체 | `local` |

**상세를 읽고 반드시 확인할 것 — 오늘 날짜 기준으로 신청이 가능한가.**
`summary` / `target` 에 접수기간이 박혀 있는 경우가 많다(예: "'26년 신규 신청기간: 3.30 ~ 5.29"). 관련도 1위라도 접수가 끝났으면 그 사실이 사용자에게 가장 중요한 정보다. 공고마다 상태를 판정해 리포트에 표시한다.

| 상태 | 판정 |
|---|---|
| 신청 가능 | 상시 접수이거나 접수기간 안 |
| 접수 마감 | 접수기간이 지남 — 다음 공고 시기와 함께 표시 |
| 조건 확인 필요 | 세대주 요건 등 사용자 프로필로는 판단 불가한 자격이 걸림 |

지원금인지 **대출**인지도 구분해 표시한다(`provision_type` 이 `현금대여(융자)` 면 갚아야 하는 돈이다). 프로필과 충돌하는 자격 요건(세대주 여부, 2촌 이내 혈족 주택 임차 제외 등)은 리포트 상단에 따로 모아 먼저 보여준다.

### 5. HTML 리포트 발행 (Artifact)

**1단계에서 "터미널에만 요약" 을 골랐으면 이 단계를 건너뛰고 7단계로 간다.** 그 선택지는 카카오톡도 함께 생략하므로 훅과 충돌하지 않는다. 나머지 두 선택지에서는 반드시 수행한다.

**카카오톡을 보내기로 했다면 이 단계를 건너뛸 수 없다.** 카카오톡은 200자라 공고 상세가 들어가지 않는다. 링크가 곧 본문이므로, 리포트가 없는 전송은 빈 전송이다. 훅은 "요청 답변" 블록에 `https://claude.ai/code/artifact/...` 가 없으면 차단한다(0건일 때만 예외).

Artifact 도구 요구사항대로 **먼저 `artifact-design` 스킬을 로드**한 뒤 HTML 파일을 쓰고 발행한다.

공고당 담을 것: 서비스명 / 소관부처·조직 / 지원내용 / 지원대상 / 선정기준 / 신청방법 / 문의처 / 복지로 상세링크.

리포트에 **반드시 함께 넣을 두 섹션**:

- **해당되지 않는 것** — 3단계에서 걸러낸 항목과 사유(연령 초과, 신청 기한 종료, 가구 요건 미달). 사용자가 검색하면 눈에 띄는 제도들이라, 왜 빠졌는지 적어두지 않으면 다시 찾아본다.
- **해당되면 더 있는 것** — 저소득·한부모·장애·다문화 등 프로필로 확정할 수 없었던 가지들. 사용자가 자기 해당 여부를 스스로 판단할 수 있게 한 줄씩.

- `<title>` 은 짧은 고유명. 예: `청년 주거복지 3선` (설명문 금지)
- `favicon`: 첫 발행 시에만 지정
- `description`: 한 문장

발행 결과 URL을 확보한다. 이게 카카오톡 메시지에 들어간다. 실측 길이 **68자**(`https://claude.ai/code/artifact/<uuid>`).

Artifact는 기본이 비공개다. 카카오톡 링크를 **휴대폰에서** 열면 카카오톡 인앱 브라우저에 claude.ai 세션이 없어 리포트가 안 보일 수 있다. 이 경우 Artifact 공유 메뉴에서 링크 공유를 켜야 한다. 전송 후 사용자에게 한 번 확인시킨다.

### 6. 카카오톡 전송 — `KakaotalkChat-MemoChat`

**1단계에서 "웹사이트 + 카카오톡" 을 고른 경우에만 이 단계를 수행한다.** 나머지 두 선택지에서는 도구를 호출하지 않으므로 PreToolUse 훅도 발동하지 않는다. 7단계로 바로 간다.

**이 구조는 불가침이다. 어떤 경우에도 변형하지 않는다.**

```
- 요청 사항
{검색 조건 요약}

- 요청 답변
{N건 추천} → {Artifact URL}
```

규칙:

- 헤더 두 줄은 **문자 그대로** `- 요청 사항`, `- 요청 답변`. 띄어쓰기 포함 정확히 일치.
- 두 블록 사이에 빈 줄 **정확히 하나**.
- `- 요청 ` 으로 시작하는 줄은 이 헤더 2개뿐. 블록을 추가하지 않는다.
- 마크다운(`**`, `#`, 백틱), 이모지 금지. 평문만.
- **답변 블록에 5단계의 Artifact URL이 반드시 들어간다.** 공고 목록을 본문에 나열하지 않는다 — 200자에 들어가지도 않고, 넣더라도 링크를 대신하지 못한다.
- **전체 200자 이내** (문자 기준 — 실측 확인됨).

예산 (총 200자):

| 항목 | 실측 |
|---|---|
| 구조 고정비 | 16자 |
| Artifact URL | 68자 |
| `3건 추천 → ` | 8자 |
| **요청 사항에 쓸 수 있는 몫** | **약 105자** |

넘칠 때는 **요청 사항 요약을 먼저 줄인다.** 구조와 URL은 건드리지 않는다.

결과가 0건일 때만 답변 블록을 링크 없이 `조건에 맞는 공고 없음` 으로 쓴다. 이게 URL 검사의 유일한 예외다.

전송 직전, 만든 문자열을 스스로 검증한다 — 헤더 정확 일치 / 빈 줄 하나 / 헤더 줄 2개 / 장식 없음 / 200자 이내. 플러그인의 PreToolUse 훅이 같은 검사를 백스톱으로 수행하며, 어긋나면 호출을 차단하고 사유를 돌려준다. **차단되면 사유대로 고쳐 반드시 재전송한다.**

### 7. 마무리

터미널에는 공고의 이름·핵심 지원내용을 요약해 보여준다. 3단계에서 걸러낸 **배제 항목과 사유**, 그리고 **추가 확인이 필요한 가지**도 함께 적는다. 여기서는 링크와 상세를 자유롭게 써도 된다(200자 제약은 카카오톡에만 적용).

이번 요청 조건이 저장된 프로필과 충돌했다면(1단계 참조) **여기서** `AskUserQuestion` 으로 갱신 여부를 묻고, [갱신] 이면 `~/.claude/bokji-profile.json` 을 다시 쓴다. 검색 전에 묻지 않는 이유: 사용자를 결과 앞에서 붙잡아 두지 않기 위해서다.

선택지에 따라 출력이 달라진다.

| 선택지 | 터미널에 쓸 것 |
|---|---|
| 터미널에만 요약 | 리포트가 없으므로 **여기가 유일한 산출물**이다. 공고당 지원내용·지원대상·선정기준·신청방법·문의처·복지로 상세링크를 빠짐없이 쓰고, 배제 항목과 확인 필요 가지도 그대로 적는다. |
| 웹사이트만 | 요약 + 리포트 URL |
| 웹사이트 + 카카오톡 | 요약 + 리포트 URL + 카카오톡 전송 완료 안내. Artifact는 기본 비공개라 휴대폰 카카오톡 인앱 브라우저에서 안 열릴 수 있다는 점과 공유 메뉴에서 링크 공유를 켜는 방법을 한 줄 덧붙인다. |

전송이 **도구 부재**로 실패했다면(훅 차단이 아니라 `KakaotalkChat-MemoChat` 자체가 없는 경우) 리포트 URL을 그대로 안내하고 "카카오톡 나챗방 도구가 도구함에 없어 전송하지 못했습니다 — https://playmcp.kakao.com/toolbox 에서 담은 뒤 새 세션에서 다시 시도하세요" 를 덧붙인다. 훅에 차단된 경우는 다르다 — 사유대로 고쳐 **반드시 재전송한다.**
